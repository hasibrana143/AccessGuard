# AccessGuard — Risk Register

Updated: 2026-11-22

| # | Risk | Probability | Impact | Rating | Mitigation | Status |
|---|---|---|---|---|---|---|
| 1 | A login script stored per organization is arbitrary JavaScript executed against the scan target | Medium | High | 🟠 HIGH | Only admins (`manage_settings`) can create one; scripts are encrypted at rest and never returned by the API; the scanner runs them in the browser sandbox of the target page, not on the server | Accepted (documented in `docs/engineering/SCAN_AUTHENTICATION.md`) |
| 2 | A login script runs once per page in crawl mode, making authenticated crawls slow | High | Low | 🟡 MEDIUM | Documented limit; cookie/header auth stays cheap; reduce `crawlConfig.maxPages` for script-auth projects | Open |
| 3 | Dependency upgrades to next 16.4.6 / prisma 6.19.3 could change runtime behaviour | Medium | Medium | 🟡 MEDIUM | Full gate suite re-run after the upgrade (typecheck, lint, 407 vitest, next build, prisma validate + generate, zero-drift migration check) | Mitigated |
| 4 | `prisma db push` on the dev database drifts from the migration chain again | Medium | Medium | 🟡 MEDIUM | `prisma migrate deploy` is the source of truth; `migrate diff --to-schema-datamodel` reports zero drift for both the dev and a fresh database | Mitigated |
| 5 | Shared test fixtures across API route suites caused cross-file user/org collisions | High | Medium | 🟡 MEDIUM | Unique e-mail per suite plus deterministic upserts; rbac/tenant-isolation mocks now use real database rows | Mitigated |
| 6 | Public onboarding scans remain a compute-abuse vector behind a single proxy IP | Medium | Medium | 🟡 MEDIUM | 5/min per client; for a shared egress IP the limit is shared — consider a signed token or CAPTCHA if abuse appears | Open |
| 7 | No E2E coverage for the new credential API | Medium | Low | 🟢 LOW | Contract tests cover auth, permission, tenancy, encryption, masking, update and delete | Open |
| 8 | Fix verification needs a Chromium binary at request time; without it every fix is unverified and no PR can be opened | Medium | Medium | 🟡 MEDIUM | Resolution order: `PUPPETEER_EXECUTABLE_PATH` → `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` → system Chromium → Playwright browser. The Docker image ships system Chromium, CI installs the Playwright browser before the unit suite. The route fails closed with an explicit error rather than opening an unverified PR | Mitigated |
| 9 | Verification is rule-level on the remediation snippet, not a full page re-scan, so destination CSS and template semantics are absent from the verdict | Medium | High | 🟠 HIGH | The fifth review reproduced a class-driven full-viewport overlay (5-H1) and a server-template expression (5-H2). Both are now closed: the repository's own CSS is judged before a write (`src/lib/css-context.ts`), a remediation may not add a class, and a template grammar in the remediation or in the destination file is refused. What remains outside the verdict is CSS-in-JS, CDN stylesheets and structural pseudo-class selectors — documented, not claimed | Mitigated — fifth review 5-H1/5-H2 closed |
| 10 | `.vue` / `.svelte` / `.astro` files fall back to an exact text match and can miss the target | Medium | Low | 🟢 LOW | Conservative fallback: it never guesses, and a missed target leaves the fix out of the PR instead of corrupting the file | Open |
| 11 | The Docker image runs Chromium as root, so the OS sandbox is disabled for the verification browser | Medium | Medium | 🟡 MEDIUM | The verification document carries a restrictive CSP, the context aborts every HTTP request and closes every WebSocket, only markup that passed the safety checks is rendered, every run has a 15 s deadline, and the route is rate limited per user. Running the container as a non-root user (and installing the Chromium sandbox packages) is the follow-up | Mitigated |
| 12 | The element is located by content, not by a source map from the scanned URL, so a match can be ambiguous or inert | High | High | 🟠 HIGH | Every identity attribute is compared and the tree is scanned under a byte budget. The fifth review reproduced template/iframe/raw-text content counted as live (5-M3) and omitted template extensions/submodules that did not make the scan incomplete (5-M4). Both are closed: the live-context scanner follows the browser, every text blob of the tree is scanned, and a submodule makes the scan incomplete | Mitigated — fifth review 5-M3/5-M4 closed |
| 13 | A verification request costs a Chromium launch and one axe run per fix | Medium | Low | 🟡 MEDIUM | The request is capped at 25 violations **before** the browser work, the route is rate limited per user, the browser is launched once per request and reused for the whole batch, and a global semaphore runs at most two batches at a time | Mitigated |
| 14 | The NVIDIA free-pool list still names `meta/llama-3.3-70b-instruct`, which the provider reports as end-of-life (HTTP 410 Gone since 2026-08-26) | High | Low | 🟡 MEDIUM | The router fails over on any 4xx, so the chain still completes — the cost is one wasted provider call per AI remediation when NVIDIA is in the pool. Found while trying to run the Strix pentest; replacing the entry needs a live check of the current NVIDIA catalogue (next AI volume) | Open |
| 15 | The Strix autonomous pentest cannot run: every configured provider refuses (Gemini free tier quota exhausted, NVIDIA model EOL, OpenAI credits exhausted) | High | Medium | 🟠 HIGH | Five independent human-agent security reviews plus one QA review covered the V23 diff, and `npm audit` covers the dependency surface. Strix must be re-run against the same sanitized export once a provider has quota — until then it is not evidence and is not cited as such | Open (blocked by provider quota, not by the code) |
| 16 | Earlier V23 hardening rounds were reported as fixed while equivalent paths remained open — a repeated closed-loop gap in how findings were verified | High | High | 🟠 HIGH | Every review now re-runs the literal prior payloads, hunts equivalent destination-aware variants, and records before/after output. A fix needs the reproduction to fail before and pass after; the fifth review still found six equivalent paths, and the closure now re-runs all of them (8/8 blocked) with permanent regressions. The gate opens only when a sixth independent pass returns READY | Open — the sixth review found eight more equivalent paths; the seventh review is the next check |
| 17 | A repository larger than the 5 MB scan budget is never patched in place, so large customers only get review files | Medium | Low | 🟢 LOW | Accepted: a complete scan is required to prove uniqueness, and a partial scan could patch the wrong file. The source-map mapping (risk 12) is the real fix | Open |
| 18 | A fix whose element occurs more times in the file than the selected fixes is normally left as a review suggestion, but when every duplicate is selected the request order could still swap the remediations | High | High | 🟠 HIGH | The fourth-review swap is closed: two selected copies of the same element with different remediations cannot be mapped (the request order is not an occurrence identity), so they stay review suggestions and the source is never patched with a swapped remediation | Mitigated — fourth-review 4-M8 closed |
| 19 | The image gate depends on `trivy-action` behaviour that is not obvious: the SARIF format drops the severity filter, so the exit code counts every severity | Medium | Medium | 🟡 MEDIUM | The workflow sets `limit-severities-for-sarif: true` and pins the scanner (`v0.76.2`). A future action upgrade may change the default again — the image scan has to be re-checked when the action is re-pinned | Mitigated |
| 20 | The third and fourth independent reviews closed their *literal* reproductions but left equivalent paths open | High | High | 🟠 HIGH | The fifth review reproduced six equivalent paths (2 High, 4 Medium) and the sixth review eight more (2 High, 6 Medium). Each closure needs a browser/destination-aware root-cause fix and a permanent regression that fails before and passes after; the seventh review must return READY before the release gate opens | Open — seventh review pending |
| 21 | The verified-fix validator and source writer reason in HTML but can write into HTML comments, JSX, TypeScript strings and framework templates, allowing untrusted text/code into customer source | High | High | 🟠 HIGH | The literal fourth-review injections are blocked. The fifth review wrote an EJS-style server expression into `.html` (5-H2); that is closed as well — a remediation with template grammar is rejected, and an HTML destination that carries template grammar is refused entirely (no patch and no review comment, because the engine would evaluate the comment) | Mitigated — fifth review 5-H2 closed |
| 22 | A fix can activate overlay-capable behavior without an inline style: an existing repository CSS class is absent from the isolated verification document | High | High | 🟠 HIGH | The inline-style entity/escape/comment bypasses are blocked. The fifth review verified and wrote `class="overlay"` and measured a fixed 1280×720 overlay in Chromium (5-H1); that is closed as well — the repository's own CSS is judged before a write, and a remediation may not add a class the original element does not have. What remains outside the judgement is CSS-in-JS, CDN stylesheets and structural pseudo-class selectors | Mitigated — fifth review 5-H1 closed |
| 23 | A fix that passes the axe rule check can still delete what the user reads (the label reduced to one character, or hidden with `opacity:0` while staying in the DOM) | Medium | High | 🟠 HIGH | The literal `opacity:0` and reduced-label variants are blocked. The fifth review wrote `opacity:0!important` (5-M2); that is closed as well — the CSS priority suffix is stripped before the hidden-content checks, `opacity:0` is rejected outright, and the verification browser decides visibility from the computed style instead of `innerText` | Mitigated — fifth review 5-M2 closed |
| 24 | Untrusted prose can still become a live link in the PR body, because GFM autolinks a bare URL without any Markdown syntax | Medium | Medium | 🟡 MEDIUM | The scheme of a URL is neutralized (`https&#58;//`, `www&#46;`); verified against GitHub's own Markdown API — the escaped text renders as plain text while the control renders as a link | Mitigated — fourth-review 4-M1 closed |
| 25 | An entity-encoded `input type=image` bypasses the resource-loader rejection and issues a customer-side request | Medium | Medium | 🟡 MEDIUM | 5-M1 showed `im&#97;ge` decoding to `image` in Chromium and reaching a local HTTP server after the write. The type value is now decoded before it is classified, and any `<input>` whose raw type carries an entity is rejected, because a partial entity table cannot mirror a browser | Mitigated — fifth review 5-M1 closed |
| 26 | A repository stylesheet the analyser cannot judge (a preprocessor at-rule, an unknown at-rule, a variable or an interpolation it cannot resolve) makes the whole destination unprovable, so fewer fixes are written into source than before | High | Low | 🟡 MEDIUM | Accepted: the fail-closed direction is what the sixth review allows, and the customer still receives the fix as a review suggestion. The reader covers plain CSS in a preprocessor file, native nesting, escapes and the common viewport units; a real preprocessor compiler would widen the coverage | Open — accepted |
| 27 | The destination CSS reader is a static reader: a rule that only becomes an overlay through a runtime value (a custom property the analyser cannot resolve, a script that writes a style) is outside its reach | Medium | Medium | 🟡 MEDIUM | A custom property that the fix changes makes the destination unprovable (fail closed). A style written by a script at runtime is outside any static analysis of the repository | Open — accepted |
| 28 | A blob whose name does not say whether it is binary (`.dat`, `.bin`) is now read, and a blob the GitHub contents API cannot inline makes the whole scan incomplete, so no file is patched | Medium | Low | 🟢 LOW | Accepted: the finding asked for the blob to be read and for the content to decide. An unreadable blob keeps the documented fail-closed behaviour (an incomplete scan cannot prove uniqueness) | Open — accepted |
